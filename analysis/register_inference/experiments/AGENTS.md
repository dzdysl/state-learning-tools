# 实验性 ngKSI 寄存器推断规则

本文件是寄存器推断算法的唯一完整规范。实验仓库只保存输入、证据和交付契约，不得复制或改写本文件的
算法语义。本目录脚本与分析仅生成弱协议先验支持的黑盒候选，不得将候选表述为 AMF 实现变量、源码
更新点或协议事实。

## 规范术语

1. 单边区域形成的候选及其按信号上下文合并后的模型统一称为“相对稳定推断”。不得另称“稳定参考组”、
   “稳定参考候选”或“参考公式”。
2. 多边区域的拆分结果称为“假设性候选”；把相对稳定推断应用到假设性区域称为“相对稳定推断迁移检验”；
   迁移不成立后对前序无下行边求前像称为“前序反推”。
3. 不再使用“分区分歧”“严格矛盾”“观察冲突”或同义状态解释候选协调。循环局部公式不同只进入下述
   交集与联合拟合流程，不额外赋予冲突语义。
4. 代码为兼容旧产物暂时保留的字段或枚举，不得直接作为面向读者的术语；更新 schema 时应迁移到本节
   规定的名称。

## 观测与候选边界

1. 当前工作流把携带 ngKSI 的 AMF 下行字段视为所属区域的更新后 `r_after` 观测；不在本工作流中推断它是更新前字段。
2. 有限 Mealy 观察等价类不证明真实 AMF 寄存器数量有限。算法只对配置的、可由 SUL/UE 观测支持的有限寄存器基生成候选；其余内部状态保持未建模。
3. 非自环且目标为 D 类状态的边可保留 `r'=7` 重置候选，优先级高于无观测保持候选；它仍是未确认先验。
4. 输入、输出均无 ngKSI 观测的边可保留 `r'=r` 最简候选；缺失观测不是寄存器未变的证明。

## 原始轨迹物化与输入契约

1. `inputs.trace` 必须是冻结外部 raw 快照内完整 `statelearner_trace.jsonl` 的字节一致
   `evidence/` 副本。先执行 `prepare_register_inference_trace.py`，再执行本目录的推断器；
   不得直接使用 live run 目录、`statelearner_trace.cleaned.jsonl`、筛选导出或手工改写的
   JSONL。
2. 预处理器必须记录源/目标路径、字节数、SHA-256、记录数、`sequence_id` 组数、选中循环
   变体到轨迹组的映射，以及 `payload_transformation: none`。目标证据已存在时仅允许校验其
   SHA-256 相等，禁止覆盖不同字节的证据。
3. 所有循环输入统一来自 `cycle_cover.sequence_export.cycles`。每项使用 `cycle_id`、
   `line_number` 和 `loop_inputs`；不得读取或恢复 `sequence_export.routes`、`route_inputs`
   或同义兼容层。
4. 对每个选中变体，组末 `sequence_inputs` 必须唯一匹配 `.seq` 行，组内记录数必须等于该行
   输入数，且每步 `abstract_io.input` 必须按序匹配。任一失败表示该 raw run 不适合当前
   推断配置，停止而不是筛选或修补记录。
5. 允许的转换仅限内存内的 JSONL 行号标注、配置字段的整数解析和配置字段的布尔解析；不得
   对证据作字段补全、重解码、去重、排序、跨会话拼接或删除。

## 类型化观察与 schema v3

1. 推断区域保持原始 `(r_before, ordered_observation_items, r_after)`。面向读者的标准写法中，信号量必须
   写为 `{s0=value}` 或 `{signal_id=value}`，数值输入必须写为 `[i0=value]` 或
   `[input_register_id=value]`；例如 `(0,{initial_uplink_context=1},[ngksi_uplink=7],0)`。
   每项保留类型、字段路径、逻辑输入、事件位置、轨迹行和出现序号。缺失、重复、乱序或身份不一致时
   报告异常，不得移位补齐。
2. schema v3 使用 `mapping.numeric_input_definitions`。每个定义具有唯一 `id`、整数路径、消息选择器和 `input_register_id`；相同 `input_register_id` 明确表示同类型输入，而不是由消息名隐式猜测。
3. 同一信号 ID 或输入寄存器 ID 在一个区域内按事件时序采用最后写入值。原始观察、覆盖链和来源消息必须同时保留；覆盖投影不能删除或改写原始证据。
4. 信号定义仍由 `mapping.signal_definitions` 驱动，消息选择器可为任意列表或唯一通配符 `"*"`。同一事件中信号按声明顺序位于数值输入之前。

## 输入寄存器与边级归属

1. 每个 `input_register_id` 对应一个输入寄存器 `r_i`。新输入在该边其他寄存器更新前写入：有输入为 `r_i'=i`，无输入为 `r_i'=r_i`。某循环从未出现该类型时标记 `unobservable_input_register`。
2. 输入寄存器以第 2 轮初始化；有该类输入的循环从第 3 轮开始拟合。除非跨边传播出现反例，本轮不得仅因信号存在而为 `r_i` 枚举常数分支。
3. 单边区域的已观察样本精确候选标记 `relatively_stable_candidate`；该标签只说明该边已观察分支相对稳定，未观察信号分支仍可为 `unknown`。
4. 多边区域采用“前序边最简、末端可观察边拟合”时，所有拆分结果标记 `hypothetical_candidate`，并记录 `region_to_edge_decomposition`、最后写入投影及最简默认等假设来源。
5. 无下行锚点的前序边默认 `r'=r`。若它带输入和信号，使用 `ite(s=1, unknown, r)`，同时仍记录输入寄存器赋值。

## 模型树规则

1. 所有信号节点统一为 `ite(s=1, true_branch, false_branch)`；不以 `s=0` 作为正向 guard。
2. `threshold_guard` 只表示可观察回绕结构 `ite(x<T,f,0)`，否则叶固定为常数 0；不显式声称一般模运算。
3. `derived_value_guard` 仅在基础叶和阈值树均失败后，从具有充分连续支持的输入寄存器值中枚举；整数 `7` 不自动具有协议语义。
4. 保留 `r'=c`、`r'=r+k`、`r'=r_i+k` 及所有精确并列树。`observationally_exact_candidate` 与 `partial_observational_candidate` 是观测状态，必须和候选等级分开记录。
5. 假设性候选先按 `cycle_id` 分别构建每个循环的最简候选，然后执行唯一协调流程：
   - 精确树交集非空：直接采用交集；
   - 精确树交集为空：合并这些循环的全部样本，重新搜索覆盖联合样本的最简候选；
   - 联合拟合仍无候选：为该具体边记录结构化 `combined_sample_fit_failed` 边级错误，候选为空，
     但继续处理其他边，并允许该边继续进入相对稳定推断迁移检验与前序反推；不得为通过流程而任意选式。
   JSON 保留各循环局部候选、交集、联合拟合和边级错误，但不再生成“分区分歧”、观察键冲突或非共识语义。
6. 相对稳定推断按完整有效信号上下文、`logical_input` 和 `logical_output` 合并单边区域；若该 I/O 不适用
   任何已配置信号，则只按 `logical_input/logical_output` 合并。相对稳定推断必须保存绑定的 `{s=value}`、
   输入寄存器槽和完整模型树，不能退化成脱离信号上下文的一条数值公式。
7. 每个相对稳定推断仍按简单叶、单阈值、`derived_value_guard` 的顺序生成。某个已接受的相对稳定推断
   首次出现 `derived_value_guard: r_i == T` 后，立即把该整数 `T` 加入本次脚本生命周期后续所有推断阶段的
   动态偏好集合；已经生成的候选不回排，配置文件不得预设 `T`。
8. 动态 `T` 偏好只改变后续精确候选的排列，不删除其他候选：若 `r'=T` 对当前全部样本精确成立，精确
   常数赋值 `r'=T` 排在最高优先级；含 `derived_value_guard: r_i == T` 的候选随后优先于不使用该 `T` 的
   同类候选；其余候选继续按既有复杂度与规范化树键排序。`r+k`、`r_i+k` 或偶然算出 `T` 的公式不等同于
   精确常数赋值。
9. 相对稳定推断迁移检验只在相同有效信号上下文、`logical_input` 和 `logical_output` 之间进行。对目标
   映射观察区域，直接把 `r_before`、边后有效 `r_i` 和 `{s=value}` 代入相对稳定推断模型树：预测值等于
   实际 `r_after` 即迁移成功；不等即迁移不成立，并尝试前序反推。没有同一 `{s}/input/output` 相对稳定
   推断时，只记录“无可迁移的相对稳定推断”，不得借用其他信号分支。
10. 前序反推只归因终止观察边之前最近的一条无 KSI 下行边；更早无下行边暂按 `r'=r` 并逐条记录。
    在本次纳入结果的全部匹配轨迹上下行 KSI 观测并集中枚举该边可能的 `r_after`，沿后续已知模型树正向
    模拟到真实终止 `r_after`，保留全部前像，再按简单叶、阈值树、派生值树搜索覆盖全部样本的公式。
    反推阶段继续使用已经激活的动态 `T` 偏好；例如允许前像同时含 `6` 和 `7` 且 `T=7` 已激活时，
    `r'=7` 排在 `r'=6` 及其他精确候选之前，但所有候选仍保留。结论始终是带保持假设和反推来源的
    `hypothetical_candidate`，不得声称确认真实实现更新。反推结果归属于被反推具体边自身的完整
    `{s}/logical_input/logical_output`；即使 `logical_input` 相同，只要 `logical_output` 不同，也不得把
    反推分支补入另一组相对稳定推断。

## 循环轨迹后处理

`cluster_cycle_trajectories.py` 是本推断完成后的独立后处理，不属于候选语言、区域构造、相对稳定推断迁移检验或前序反推的组成部分。它只能读取已生成的 `candidates.json`：以同一 `cycle_id + sequence_line` 的直接区域为有序轨迹，只在相同 `logical_input/logical_output/isInitMsg` 切片内进行比较。它纳入相对稳定推断和 `region_edge_count > 1` 的假设性候选；必须排除 `minimal_predecessor_default`、所有前序反推、迁移失败和无匹配相对稳定推断 I/O 的对象。schema v2 将 R3–R9 的七点周期复制为 14 个分析点，R3/R10 仅允许严格同相位校验或由 R10 补齐缺失 R3 `i`，不得趋势外推；模式补齐点不得表述为实测。信号不进入距离，低辨别力或混合切片轨迹不得进入距离矩阵、簇数选择或迁移一致性。其分簇结果是后续比较证据，不得反向改写候选、迁移检验或前序反推结论。

## 轨迹归类算法 B：二维公式候选

`trajectory_formula_discovery.py` 实现独立于上述距离聚类的轨迹归类算法 B。第一阶段选择一个或多个
`logical_input/logical_output`，以 EID 为基本对象分别分析 `r_before–r_after` 与
`r_i–r_after`；不得读取距离聚类结果、候选类型标签或自动簇编号。每个 EID 拥有自己的精确候选，
规范化候选组按 input/output 和投影隔离，只作允许重叠的反向索引，不将 EID 唯一分配到类别。信号上下文
随轨迹保留作审计，但第一阶段不按信号值拆分或拟合。

1. 只使用真实 R3–R10 点。缺失输入寄存器值只能按冻结 trace、配置和
   `cycle_cover.sequence_export.cycles` 在同一序列内重放最近输入；不得读取 14 点模式补齐。
2. 候选语言按 `r'=c`、`r'=r+k` 或 `r'=r_i+k`、`ite(x<t,A,B)` 由易到难精确搜索。
   顶层常数候选只能由同一条轨迹内至少两个不同 x、单一 y 且实际存在 `dx!=0,dy=0` 有向段的水平轨迹
   建立；多个静态点轨迹不得拼接为水平线。两个不同 x 是有限证据，至少三个不同 x 是核心候选。非常数
   单位仿射式至少需要三个不同 x。主分支至少覆盖三个不同 x，分裂树尾部分支仍允许单点常数。
3. 已观察 x 有整数缺口时仍保留精确候选，并分别记录 `covered_x`、`missing_x` 与
   `observationally_exact_with_gaps`；不得把缺口外推为验证结果。产生相同观察划分的整数阈值折叠为
   一个规范阈值和 `equivalent_threshold_interval`。
4. 单条投影轨迹去重后只有一个坐标时是静态点轨迹；只有一个 x、多个 y 时是纯铅垂轨迹。两者均不建立
   公式、不进入拟合门槛、覆盖统计或方向计票。它们落在由有效非退化轨迹建立的公式上时只记相容证据，
   否则保留为未解决退化点，均不否决公式。同一 x 的两个不同 y 是弱铅垂证据，至少三个不同 y 是核心
   铅垂成分；铅垂成分始终是结构描述而不是更新公式。
5. 方向只按每个 EID 去重后的有序端点计票。`dx>0`、`dx<0` 分别记正向和反向，自环退出计票，
   铅垂段、跨公式成分段及候选外段分别记录。方向是审计证据，不是公式拟合门槛。
6. schema、中文报告和离线页面必须保留完整循环来源、input/output、信号上下文、退化类型、原始重复
   支持、公式作用域和候选组关系；页面显示标准寄存器更新公式并使用全体数据固定视域与等单位二维轴。
7. 稳定性推断聚合只联合 `relatively_stable_inference.groups[*].source_edge_ids` 对应的完整轨迹，不得把迁移
   成功或其他假设性边并入基准样本。每个 input/output 先分别分析两个投影：整个投影只有一个 x 的铅垂
   结构不参与公式选择；能精确解释全部稳定样本的简单公式优先，两个投影同时满足时保留全部等可能候选。
8. 没有完整简单公式时才允许跨投影分裂。当前输入寄存器投影候选的全部不匹配样本必须只集中在一个
   `r_i=T`，且该值必须形成铅垂成分；当前公式须解释全部 `r_i!=T` 样本，另一投影候选须解释全部
   `r_i=T` 原始三元组。组合后的 `derived_value_guard` 树必须对该 I/O 的全部稳定样本逐点精确验证；
   `T`、I/O 和分支公式均由数据发现，不得硬编码。
9. 稳定组的信号上下文必须唯一。信号值只作为聚合公式适用条件和审计字段，不生成信号根节点；不适用
   信号的 I/O 明确标记为不适用。混合投影可在 JSON 和报告中保留局部候选，但不得强行选择最终树。
10. 页面初始显示二维公式候选，并允许切换到预先确定性生成的稳定性推断聚合结果；筛选只改变画布可见
    轨迹，不得在浏览器中重算聚合公式。两阶段均不执行旧迁移检验、旧前序反推或全 DOT 推广，也不得反向
    改写原寄存器候选。
11. 前序最简归因直接读取所选 input/output 的全部假设性 `direct_regions`，旧迁移成功、迁移失败及无匹配
    状态只作审计，不得作为筛选条件，也不得读取旧前序反推候选。只选择 `region_edge_count=2`、R3–R10
    完整且三元组循环内变化的轨迹；静态点轨迹不参与不变推断或反向集合前像。
12. 长度2轨迹的全部三元组必须落在同 input/output 的稳定源三元组并集内，且每个实际变化投影按 EID
    去重有向段的主要方向须与稳定源一致，才允许为具体前序 EID 记录条件性 `r'=r`。该结果是可反驳的
    前序最简不变推断；相同 EID 由不同末端 I/O 重复支持时须保留全部来源，不得推广到其他同 I/O EID。
13. 未落入者只使用稳定性聚合的最终树，在已记录全局值域逐样本枚举前序事件的允许 `r_after`。结果是
    事件级集合前像，不推断前序边公式。若R3–R10共享多个前像值，以“候选赋值方案”分别保存跨重复采用
    同一值的附加假设；不得使用“世界”一词，也不得把方案值提升为边级常数公式。
14. 获准的具体 EID 保持公式只表示前一条真实 KSI 下行的可观察值连续延伸到该边，不是新的可观察下行
    锚点。延伸从原区域的 `previous_output` 开始；中间一旦出现任何非延伸假设性边，连续性立即失效，
    后续保持边不得自行恢复连续性或建立伪边界。事件级集合前像只作用于其证据轨迹和对应候选赋值方案。
    只执行一轮重划，不在同轮重新拟合。伪边界不是独立稳定证据；新增长度1真实末端区域仅在R3–R10
    完整且三元组动态变化时标记为下一阶段可稳定性推断，静态区域保留为退化证据。
15. 页面第三模式称为“前序最简与重划分”，必须区分真实下行、伪保持和伪反向边界，支持候选赋值方案
    切换；不得显示不存在的前序边公式。JSON、报告和页面须明确条件性、事件级、单轮和不拟合边界。
16. 新稳定推断只读取前序重划后标记为下一阶段可稳定性推断的完整动态长度1区域。每条新轨迹必须同时
    满足：三元组落入相同 input/output 的旧稳定轨迹点集、去重有向段主要方向一致、旧聚合树逐点精确，
    才可直接复用旧聚合公式；否则只在相同 `input/output+s` 内联合旧、新样本重新执行稳定性聚合。
17. 新稳定推断按真实 `isInitMsg` 分支保留样本来源与验证计数。两个已观察信号分支的规范模型树不同时，
    使用 `ite(s=1,true_branch,false_branch)` 并逐点验证；规范树相同时必须化简为单一公式，不保留冗余

    不强行选择公式。

    情景控件、卡片或画布；新增“新稳定推断”模式，显示最终公式、分信号证据、旧公式复用或同信号联合
    重聚合状态。筛选只控制轨迹可见性，不得在浏览器中重新推断。

    边。真实 R3–R10 全部匹配者记为“稳定性推断（迁移）”；存在本阶段未处理的长度3或长度4反例时，
    整条边记为“暂不迁移”。剩余完整长度2区域允许一次事件级前序反推：先在已记录全局值域保留数学
    前像，再读取该 input/output 旧稳定输入投影的唯一核心铅垂成分 `x=T`；当 `T` 位于每轮前像集合时，

    水平和二维拟合门槛；事件级伪值可以验证末端迁移，但静态前序轨迹不得据此拥有常数公式。本阶段只
    生成独立中文报告，不修改候选 JSON、算法 B 机器结果或页面。

## 报告边界

- 候选应同时报告公式、对齐异常、覆盖链、拆分假设、未观察分支和可用反例。
- 同一消息或同一 I/O 标签只能提出共享语义候选，不能直接证明 AMF 使用同一个源码处理函数。
- 循环内精确性与循环外泛化必须分开；共享或拆分结论应由后续后缀、留出轨迹及对应版本源码对照继续检验。
- schema v3 命令必须提供 `--report`。Markdown 是 H13 式四列固定布局摘要，覆盖每个具体 DOT 边组。
  Excel 审计工作簿只有用户明确要求时才提供 `--workbook` 生成；未请求时不得创建工作簿、预览或
  工作簿元数据。请求时，JSON 同时记录工作簿哈希、完整性与行数。
- Markdown 摘要固定为“循环、边与节点 / 边级候选 / 输入寄存器 / 候选等级”四列。它保留全部
  全局并列候选，把 `cycle_id` 展开、`V01…` 变体、循环局部候选、交集、联合拟合、迁移和反推材料
  交给 Excel 与 JSON；消息对仍在 `/` 后换行。
- Excel 只保留“循环边使用”工作表。循环主键使用 `cycle_id`，变体使用稳定 `V01…`；不显示环内
  序号。每个 `edge_samples.cycle_id` 都须独立出现，即使同一边已在其他循环出现；候选类型、本循环
  候选、最简交集或联合拟合、相对稳定推断、迁移检验及首个反例必须在同一行可读；另以“反推状态”
  和“反推候选与假设”两列展示对应循环的最近前序边反推，不能把反推公式并入原前向候选。
- 工作簿中的并列公式使用 `① … ｜ ② …` 横向排列，不以多段纵向树撑高行；JSON 继续无损保存完整
  公式树、循环局部候选、交集、联合拟合、全部迁移与反推样本、原始重复样本和区域快照。交集为空时
  必须展示联合拟合结果；联合拟合无候选时展示边级错误并继续其他阶段，不得输出带有临时冲突术语
  或任意替代公式的结果。
- 面向读者的 Markdown 与 Excel 使用统一展示简写：`unknown/<reason>` 显示为 `unknown`，
  `r_i[ngksi_uplink]` 显示为 `r_i`，输入寄存器更新不显示括号内的观察来源；候选类型、观测状态、
  协调状态、路线类型与候选作用域使用简明中文。JSON 保留未压缩的公式树、状态枚举、观察原因与更新来源，
  因此展示简写不得改变候选语义。
- 工作簿预览 PNG 只写入系统临时目录；artifact-tool 自动产生的
  `<workbook>.inspect.ndjson` 是检查中间文件，生成器在校验后必须删除，且不得写入实验记录或 Git。
- 报告具体实例时必须列出 EID、`src/dst`、`input/output`、上行与下行 KSI、`{signal=value}`、
  `[input=value]` 和映射后的完整观察区域，不得只列边号或公式。
- 交付前验证配置声明的边组、循环、变体与循环—边使用覆盖。工作表全部单元格水平/垂直居中，A-I
  使用紧凑列宽，冻结表头、启用筛选和换行；使用 artifact-tool 生成 XLSX，并渲染唯一工作表检查
  没有截断或不可读的长文本。
